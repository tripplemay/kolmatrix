### 质量门规则（src/lib/kol-sync/quality.ts）

2. **Zombie**：lastUploadAt > 90d → skip（当前未武装备）
3. **NSFW**：brandSafetyRating questionable/unsafe → skip（当前未武装备）
4. **Double-low score**：relevance_score < 0.2 AND influence_score < 0.2 → skip

### 关键结论

1. **806 中 92%（740 条）是 <500 粉丝的真 spam**，恢复价值极低
2. **最有恢复价值的是 YouTube 500-999 段（20 条，7 含邮箱）** — 这些是 <1000 粉但可触达的商务频道
3. **Instagram 拒绝率 62% 是最大浪费区**，但被拒的主要是 <500 粉真 spam（252 条），边缘区仅 38 条
4. **放宽 quality gate 到 500 粉阈值可恢复 185 条（6%），价值有限**
5. **YouTube 93 条 spam 中有 29 条带商务邮箱**（has_business_email=true），即使 <1000 粉也值得邮箱解锁

### 建议

| 选项 | 动作 | 恢复量 | 风险 |
|---|---|---|---|
| A（最小） | YouTube spam 仅不拦 has_business_email=true 的 | 29 | 低 |
| B（中等） | 全平台放宽 followers 阈值到 500 | 185 | 中（导入低质 KOL） |

| **推荐** | **C — 平台差异化 + email 信号加权** | **~36** | **低** |

## Part 2: 2584 软删旧源 — 硬删风险

### 数据来源
kolmatrix prod DB `kol` 表，`deleted_at IS NOT NULL`。

### 数据画像

| 指标 | 值 |
|---|---|
| 总数 | 2584 |
| 平台 | 全部 YouTube |
| 来源 | metadata.source = 'youtube-api-daily' |

| ≥100K 粉丝 | 968（37.5%）|

> 注：这些是旧 YouTube Data API 源积累的大号，数据价值高但无邮箱。

### 硬删风险评估

| 风险维度 | 结果 | 风险等级 |
|---|---|---|
| **唯一索引碰撞** (tenant,platform,handle) 与活跃 KOL | 0 冲突 ✅ | **无风险** |
| **唯一索引碰撞** (tenant,platform,external_id) 与活跃 KOL | 0 冲突 ✅ | **无风险** |
| **外键依赖** kol_campaign | 11 条引用（11 个 KOL 关联历史 campaign） | **低风险** |
| **BL-091 收割消费** | 2535 条 UC id 已被 F003 收割投入 apify-kol 种子 | **无种子丢失** |
| **来源溯源** | 2584 条是旧源→新源映射的唯一 record | **中风险** |

### 详细分析

**FK 依赖（11 条）：**
11 个软删 KOL 仍在 kol_campaign 表中有引用。硬删前需先清理这些关联记录（或 detach）。数量少，操作简单。

**BL-091 种子消费：**
F003 已从 2584 条旧源中收割 2535 个 UC id 通过 POST /admin/seeds 投入 apify-kol。当前这些 id 已作为 manual_seed 种子存在于 fork：
- 部分已被 worker 消费并入库（succeeded）
- 剩余仍在队列/待充值后消费

硬删 kolmatrix 数据**不影响** fork 中的种子 — 种子已独立存在于 apify_kol DB。

**来源溯源性：**
2584 条是唯一记录「旧 youtube-api-daily 源中哪些 UC id 对应哪些 kolmatrix.kol 行」的数据。硬删后无法追溯：
- 旧源→新源映射关系（哪些旧 KOL 已被 feed 为种子）
- 历史审计（为什么 2535 个 UC id 被选中收割）

### 建议

| 选项 | 动作 | 存储节省 | 风险 |
|---|---|---|---|
| A（保留） | 不硬删，保留作审计轨迹 | 0 | 无 |
| B（清理FK后硬删） | 清理 11 条 FK → 硬删 2584 | ~数 MB | 低 |
| C（归档后硬删） | 导出 CSV backup 到 docs/archive → 硬删 | ~数 MB | 低-中 |
| **推荐** | **C — 归档到 docs/archive/BL-094-soft-deleted-2584.csv 后硬删** | **~数 MB** | **低** |

## 综合建议

1. **质量门（806）**：推荐 C 方案（平台差异化 + email 加权），YouTube 的 has_business_email 信号很强（526/809=65%），哪怕 <1000 粉也值得解锁邮箱。仅恢复 ~36 条，不影响整体质量。

2. **软删清理（2584）**：推荐 C 方案（先归档 CSV 再硬删），保留审计轨迹后释放 DB 空间。需先清理 11 条 kol_campaign FK 引用。

3. **实施优先级**：质量门放宽 > 软删清理（前者有即时业务价值，后者纯维护收尾）。
