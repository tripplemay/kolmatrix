## Root cause

`cls-culprits-insight` audit pointed at:

```
selector: div.ml-[240px] > main.flex-1 > div.mx-auto > div.grid
snippet : <div class="grid gap-6 lg:grid-cols-[260px_minmax(0,1fr)]">
score   : 0.347965
boundingRect.height: 1039  (filter sidebar + KOL grid section, taking
                            nearly the full viewport)
```

i.e. the **entire** match workspace below the KPI strip moved as a single
block on every Suspense flush.

Tracing upward, the shift came from the F011 Suspense fallbacks:

1. **`QuickStatsSkeleton`** declared `h-[88px]` — but the real `<QuickStats>`
   renders a `grid grid-cols-2 gap-4 lg:grid-cols-4` of four `<StatCard>`
   blocks, each `p-6 + label + text-3xl value + trend row` ≈ **150 px** on
   lg+. On Lighthouse Desktop preset (1350×940) this is the lg breakpoint,
   so the real height is ~150 px in a single row. The Suspense swap therefore
   dropped a 62 px (88→150) layout reservation onto the page, pushing the
   1039 px workspace grid below it down by 62 px.

2. **`SaveSearchControlsSkeleton`** declared `h-9 w-44` (36×176 px), but the
   real `<SaveSearchControls>` renders a Button (~120 px) + "My Saved
   Searches (N)" label (~150 px) + `<select>` dropdown (~180 px) inside a
   `flex items-center gap-3` ≈ 460 px total. With the parent `<header>`
   using `flex-wrap`, the swap from narrow placeholder to wide real
   component risked reflowing the header from 1 line to 2 lines on
   ambiguous viewport widths.

The combined effect of both Suspense streams was attributed by Lighthouse
as a single `0.348` shift score on the workspace grid because both fallbacks
sit above it.

## Fix (commit `cadbda5`)

`src/app/[locale]/(app)/match/page.tsx`:

1. Rewrote `QuickStatsSkeleton` to render the **exact same outer structure**
   as `<QuickStats>` — `grid grid-cols-2 gap-4 lg:grid-cols-4` plus four
   `h-[150px] bg-surface-low rounded-[16px] animate-pulse` placeholder cards.
   The Suspense flush now swaps content with zero layout reservation drift.

2. Rewrote `SaveSearchControlsSkeleton` to mirror the real component's two
   inline slots — a 32×128 Button placeholder + a 28×280 label+select
   placeholder inside `flex h-9 items-center gap-3`. The wider footprint
   prevents any header reflow on swap.

Both skeleton rewrites preserve the F011 fidelity contract (`glass-panel
animate-pulse` class pattern; `bg-surface-low` carries the panel base
treatment) so `tests/unit/bl070-f011-suspense-stream.test.ts` continued to
pass without changes.

## Sediment candidates (BL-070 done aggregate)

New for v0.9.23 (Generator side, this fix-round):

- **#29 Suspense fallback skeletons must mirror real component's outer
  structure pixel-for-pixel**, not just inherit a `glass-panel
  animate-pulse` class. A skeleton whose total height differs from the
  real component will cumulate into CLS proportional to the height of all
  downstream content (here 1039 px shifted by 62 px → score 0.348). The
  cheapest defense is to render the *same* grid + the *same* number of
  placeholder cards at the *same* card height. Generic single-element
  fallbacks are a CLS trap.
- **#30 Suspense fallback widths inside `flex-wrap` parents must match the
  resolved component's width** (or be wide enough to never force a wrap).
  Even when CLS-attribution looks "vertical", the actual trigger can be a
  horizontal flex reflow caused by a too-narrow placeholder.

(These extend #26-28 from the Generator-side fix-round 2 reflections.)
