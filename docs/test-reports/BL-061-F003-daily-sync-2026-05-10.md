## §2 验收 SQL（spec §4.F003 + amendment）

### §2.1 总量 pct（amendment 后阈值 ≥5%）

```sql
SELECT COUNT(*) AS total,
       COUNT(engagement_rate) AS non_null,
       ROUND(COUNT(engagement_rate)::decimal / COUNT(*) * 100, 1) AS non_null_pct
FROM kol
WHERE metadata->>'source' = 'apify-kol' AND deleted_at IS NULL;
```

| total | non_null | non_null_pct |
|------:|---------:|-------------:|
| **1231** | **83** | **6.7 %** |

**结论：6.7 % ≥ 5 % 阈值 → PASS（user choice C amendment 落地）**

> SQL 走 `sudo -u postgres psql kolmatrix_staging`（superuser bypass RLS）。普通 `kolmatrix_app` role 跨 tenant 默认走 RLS 看 0 行，不适合 ops 全量验证（5/10 F002 排查中重要发现）。

### §2.2 Platform-level breakdown（spec amendment 新增 — 作 BL-062 基线）

```sql
SELECT platform,
       COUNT(*) AS total,
       COUNT(engagement_rate) AS non_null,
       ROUND(COUNT(engagement_rate)::decimal / COUNT(*) * 100, 1) AS pct
FROM kol
WHERE metadata->>'source' = 'apify-kol' AND deleted_at IS NULL
GROUP BY platform ORDER BY platform;
```

| platform  | total | non_null |  pct  | 备注 |
|-----------|------:|---------:|------:|------|
| instagram |    37 |        0 |  0.0% | TikHub upstream 抽风，fork §6.3 known issue；profile 数据全空 |
