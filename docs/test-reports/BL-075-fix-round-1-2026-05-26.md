## Root cause investigation (Generator)

Staging + prod both pointed `APIFY_KOL_BASE_URL=http://localhost:3003`
at a port that had been captured by an unrelated Next.js app
(`/srv/workbench/.../frontend`, next-server v15.5.18). The
`apify-kol-service` docker stack exited 2026-05-16 01:25 UTC with
`failed to bind host port 0.0.0.0:3003/tcp: address already in use`
and never came back. KOLMatrix's daily-sync therefore HTTP-GETs the
workbench, gets a 307 redirect to a login HTML page, and the adapter
returns `apify-kol: response was not valid JSON: Unexpected token '<'`.
Pre-existing 10-day infra outage, unrelated to BL-075 code.

This sits at the "infrastructure layer" per
`role-context-generator.md §"扩范围 vs 单点修"` — escalated to the
user before touching. User picked **Option A: fix apify-kol-service
infra**.

## Fix sequence (ops + 1 small code change)

### 1. Move apify-kol-service to host port 3004

`/opt/apify-kol-service/docker-compose.yml`:
- `"3003:3003"` → `"3004:3003"`
- Backup `.bl075-bak` left in place
- `sudo docker compose up -d --build` recreates both containers
- Verified: `apify-kol-service-service-1` healthy, `/kol?platform=youtube&limit=1`
  returns real JSON (e.g. `GamingBolt` channel data).

### 2. Update KOLMatrix env files (prod + staging)

`/opt/kolmatrix/.env.production` + `/opt/kolmatrix-staging/.env.staging`:
- `APIFY_KOL_BASE_URL=http://localhost:3003` → `:3004`
- Backups: `.env.{production,staging}.bl075-fix.20260526-152808`
- `set -a; source .env.production; set +a` + `pm2 reload kolmatrix --update-env`
  (same pattern as BL-075-F002; pure `--update-env` does not re-read
  `env_file`, see proposed-learnings #10)
- `/proc/<pid>/environ` confirms the new value reached the running cluster
  (prod 2 workers + staging 1 fork)

### 3. Generator side: `--enrichment-limit=N` on daily-sync

Even with apify-kol healthy, `--dry-run` intentionally skips the
enrichment block (`if (!deps.dryRun)` guard), and a full real run
would process ~3851 staging NULL rows × 3.5 s LLM gap ≈ 4 hours —
too long for a verification window.

`scripts/kol-sync-daily.ts`:
- `parseArgs` gains `enrichmentLimit: number | null`.
- `--enrichment-limit=0` (or unset) = no cap (cron-safe; legacy lines
  keep working).
- `--enrichment-limit=N>0` threads through `DailyRunDeps` →
  `enrichKolsForTenant({ limit })` so the helper stops after N rows.

`tests/unit/kol-sync-daily.test.ts`:
- 3 new parseArgs cases (positive / zero-means-uncapped / rejection).
- All 10 tests pass.

Commit: `07acad6 fix(BL-075-F003): --enrichment-limit CLI for daily-sync`.
