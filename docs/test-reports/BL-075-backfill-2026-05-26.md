       k.language, k.country_code,

Review criteria (best-effort, not gating):
- _language_ correct iff bio + handle suggest the inferred ISO 639-1 (or null on insufficient signal).
- _country_ correct iff bio / handle / brand mentions support the inferred ISO 3166-1 alpha-2 (or null on ambiguous).
- Audit notes any obvious mis-classifications (false positive on country, language mismatch with audience focus, etc.).

**Interim observation:** zero false-positive country mis-tags in the
sample. The LLM is conservative — it returns null on ambiguous bios
rather than guessing. This biases the fill rate down (low recall) but
keeps precision high, which is the right trade for a marketer-facing
filter (false positives would silently mis-route campaign outreach).

## §4 Failure modes observed

- **429 (HTTP rate limit) — aigcgateway 30 RPM cap.** Aggregate per API key, shared with BL-067/068/069 normal user traffic. Mitigation: enrichment-stage in-process gate at 3500 ms (≈17 RPM) leaves headroom for normal users. fetchWithRetry 1.5s jitter is not a substitute for the gate.
- **Daily cost cap (`AiDailyCostExceededError`).** Cost-cap uses `count × $0.01` estimate while real per-call cost is ≈ $0.0009 (~11× over). Mitigation: per-subprocess env override `AI_DAILY_COST_USD_PER_TENANT_MAX=500`.
- **Model returns `{country: null}`.** Expected behavior — many bios have no geographic signal. Confidence-gated >=0.5 honesty is correct per spec §1.3 (best-effort, no forced guess).
- **franc returns `und` / outside the 34-language allowlist.** Same handling: column stays NULL rather than written with a code the UI cannot render.
