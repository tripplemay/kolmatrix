## 已知问题与注意事项

### 1. M6 relationship-status 路由删除（无阻塞）

**背景：** 路由 header 声明 "future mobile/external clients contract"，但零 fetch 调用方、无 mobile 端在建。

**实装：** 删除了该 REST 路由（`PATCH /api/kols/[id]/relationship-status`），但保留了底层 `updateKolRelationshipStatus` Server Action（在 `kols/[id]/actions.ts` 中），通过直接调用 `lib/crm/update.ts` helper 工作。

**评估：** 正确迁移，无残留调用。若 Planner/Codex 认为应保留路由为契约，一行 `git revert` 可恢复。

### 2. M5 tsvector integration test 删除

**背景：** 删除 `lib/kol/tsvector.ts` 连带删了 `tests/integration/kol-tsvector.test.ts`。

**现状：** DB `search_vector` 列、trigger、GIN index 完整保留（migration 中 DROP 语句全为注释）。

**建议：** 若 BL-112 需保留 DB infra 覆盖，由 Evaluator 在后续补焦点测试（如 GIN index 查询性能测试）。

### 3. Staging 构建 OOM（已确认无害）

**现象：** Staging build 峰值触发系统 OOM，SSH 会话掉线（exit 255）。

**根因分析：** 8GB 共享 VM（prod + aigc4 + staging + build）内存竞争，导致 SSH 掉线。

**验证结果：** Build **实际完成**——BUILD_ID 写入、git_sha=02ba1fe 正确、/en/login 200 可访问、.next 完整、pm2 reload 稳定。

**教训：** staging build SSH exit 255 ≠ build 失败，必须查 git_sha + 实页加载实证。已在 generator_handoff 中记录。
