# BL-067 Fix-Round 1 — Staging Chunk 404 Root Cause + Fix

> 状态：**fixing → reverifying（待 Reviewer 复验）**
> 起因：`docs/test-reports/BL-067-verifying-blocker-2026-05-15.md` Reviewer FAIL，staging `/en/campaigns/[id]` 进入 ErrorBoundary，浏览器控制台 `ChunkLoadError` + `GET /_next/static/chunks/0saadcx7i3a-c.js => 404`。
> 修复：Generator johnsong / commit 待

## 根因（infrastructure 层 — 非 BL-067 代码引入）

### 现象链

1. Reviewer 在 staging `/en/campaigns/<uuid>` 看 ErrorBoundary，浏览器报 `0saadcx7i3a-c.js` 和 `04y1y7eon_72b.css` 两个 chunk 404 + Content-Type `text/plain` + body `Not found`（9 字节）
2. 验证 chunks **实际在磁盘**（`ls /opt/kolmatrix-staging/.next/static/chunks/` 可见）
3. 但 `curl https://staging.../<chunk>` 返 404
4. Nginx 配置 `proxy_pass http://127.0.0.1:3002`，所有 `/_next/static/*` 透传 Next.js 进程，无 Nginx static handler — 排除 Nginx 配置错
5. Next.js 进程 PM2 uptime=12932s（~3.5h，对应 F001 deploy），后续 F002-F006 staging deploy `pm2 restart --update-env` **看似 success 实际未真正重启**
6. `/var/log/pm2/kolmatrix-staging-error.log` 末行：`Error: Could not find a production build in the '.next' directory ... production-start-no-build-id`
7. 检查 `.next/`：**`.next/BUILD_ID` 文件缺失**，但 `.next/build/`、`.next/turbopack`（0 字节）等 Turbopack 输出 artifacts 存在

### 根因

**Next.js 16.2.4 默认 `next build` 走 Turbopack**，Turbopack 生产构建**不写 `.next/BUILD_ID`** 文件（只在 `.next/static/<BUILD_ID>/` 子目录里编码 BUILD_ID）。但 `server.js` 用 `next({ dev: false })` 加 `app.prepare()` 启动，`app.prepare()` 内部还在用旧 webpack-build 的 `.next/BUILD_ID` 文本检查 → 抛 `production-start-no-build-id` → 进程启动失败 → PM2 退到旧 worker → 旧 worker 内存里 build manifest 不含新 BUILD_ID 引用的 chunks → per-chunk 404。

这是 **Next.js 16.2.x 上游已知的 Turbopack 生产构建支持不完整**。CLI flags 上 `next build` 提供 `--turbo` / `--turbopack` / `--webpack` 三个选项；不传等于 Turbopack 默认。

### 影响时间窗

- BL-067 F001 staging deploy（dd7870c, 06:14 UTC）走 Turbopack build 后，pm2 进程仍能起来（可能那次 BUILD_ID 刚好侥幸写入了）→ uptime=12932s 从那时算
- F002-F006 每次 deploy 都跑 Turbopack build → `.next/BUILD_ID` 在某次 build 后丢失 → `pm2 restart` 启动的新进程崩 → PM2 fallback 旧 F001 进程
- 用户验证 staging health=healthy 看不出差异（health 不查 BUILD_ID），但前端 chunk 404 暴露问题

## 修复

### 立即修（Generator 已执行）

1. `infrastructure/deploy-staging.sh`：`next build` → `next build --webpack`；同 commit 加 `rm -rf .next/build .next/turbopack .next/static/[A-Za-z0-9]*` 清旧 Turbopack 残留（不动 `.next/cache` 保 build 加速）
2. `scripts/deploy-prod.sh`：同样的 `--webpack` flag + Turbopack artifact cleanup
3. `package.json` `"build": "next build"` → `"build": "next build --webpack"`（覆盖 CI + 本地 `npm run build`）
4. SSH staging 手动跑 `rm -rf .next + next build --webpack + pm2 stop+start` 恢复 staging（保留 .next/cache）
5. 验证 staging git_sha + chunks + campaign detail page
