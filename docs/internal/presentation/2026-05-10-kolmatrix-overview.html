开场命题

1 人 + AI 落地企业级 SaaS 的瓶颈，
不是模型，是 协作方法论

  • 体量 — 5 国语言 / 4 平台数据 / 多租户 RLS，传统估算 4-5 人 × 3 个月
  • AI 单独不可控 — 让 AI 自评 / 越权改架构 / 上下文塞满 都会失控
  • 多 AI 协作无方法论 — agent 互通信容易陷入幻觉循环，现成框架几乎没有
三难叠加，意味着不能简单说"用 AI 写就好了" — 必须先解决方法论。
KOLMatrix 第一幕 · 价值
问题全景

让 AI 单独写代码，到底会怎样？

单 agent 维度
字面假设 + 自评失控
• 假设 role 是 'admin'，真实是 'tenant_admin' → 上线踢回
• 单测 mock PASS，prod 真数据 41/50 触发 zod parse error
• AI 评自己的代码会说"我写得很好"
• 越权直接改架构、绕过 spec
多 agent 维度
上下文 + 协作复杂度
• 上下文塞满后丢状态，第二次会话从零开始
• 多 agent 互通信，幻觉循环无人停下来
• 跨设备 / 跨工具 / 跨会话无法接力
• 角色边界模糊，谁都不该写但谁都在写
单 agent 的失败模式 × 多 agent 的协作复杂度 = 复杂度雪球。
靠"挑更好的模型"或"多开几个 agent"解决，越加越乱。

KOLMatrix 第二幕 · 核心理念
主线 · 之一

三角色不重叠 — 无人评估自己的工作

把"规划 / 实现 / 验收"三个职责分给不同角色 + 不同 AI 工具，强化边界。

Planner
规划 / 仲裁
读 backlog · 写 spec · 拆 features.json · 做架构决策（ADR）· 出现争议时仲裁
Generator
按规格写代码
不发明需求 · 不评估自己 · 只把 spec 翻译成可运行代码 · 不准写自己的测试
Evaluator
设计测试 + 签收
独立工具（Codex），完整拥有测试域 · 输出 PASS/FAIL · critical 修复必带回归测试
铁律：Planner 不准改产品代码，紧急 hotfix 也走流程。
Generator 用 Claude，Evaluator 用 Codex — 用不同工具把"自评"从源头切掉。
KOLMatrix 第二幕 · 核心理念
主线 · 之二

状态机驱动 — 硬约束 > 自觉规则

7 状态硬性流转，每个状态只允许特定角色操作。progress.json 是唯一真理源。

new→ planning→ building→ verifying⇄ fixing⇄ reverifying→ done
入口检查
读不到自己的状态就退出
AI agent 启动第一件事就是读 progress.json 的 status —— 不匹配自己的角色就直接退出。不靠它"自觉"，是状态机硬不让它干。
批次类型
普通 / 混合 / Codex-only
每条 feature 有 executor 字段标 generator 或 codex。Codex-only 批次（压测 / 安全审计）跳过 building 直接进 verifying。
KOLMatrix 第二幕 · 核心理念
支撑这一切的基础设施

让三角色跑得稳的底层能力

分层记忆（T0 / T1 / T2）

  • T0 必读 — 项目状态、环境信息（≤30 行）
  • T1 角色 — 当前角色行为规范（≤50 行）
  • T2 按需 — 触发条件命中才加载
上下文窗口是稀缺资源，分层加载 = 节流

Git 作为协作总线

  • progress.json — 阶段 + 角色分配
  • .auto-memory/ — 跨 agent 共享记忆
  • .agent-id — 不入 git，本机身份隔离
早上台式机当 Planner，下午笔记本当 Reviewer — 跨设备无缝接力
框架沉淀

这套规则已独立为 tripplemay/harness-template repo — 下一个项目从 day 0 就有完整工作流。

KOLMatrix 第四幕 · 经验教训
最终 takeaway · 可外溢到任何项目

三条可复用经验

01
不让 AI 评估自己的任何产出
Generator 用 Claude，Evaluator 用 Codex — 用不同工具把"自评"从源头切掉。规划 / 实现 / 验收不能由同一 agent 兼任，哪怕它"能力很强"。
02
AI 协作的核心，不是 prompt，是状态机 + 记忆分层
协作是"我设计流程，AI 走流程"。没有状态机 → 失忆 / 重复劳动 / 无法接力；没有记忆分层 → 上下文爆炸。
03
过程产物 = 产品的一部分
spec / ADR / signoff 不是"开发废纸"，是工程纪律的载体。纪律可以外溢 — harness-template 已开源，下个项目直接复用。
